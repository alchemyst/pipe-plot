# Refinement issue #34: accessible plots and plot operations

## Change

The custom Canvas plot now supplies a SwiftUI `accessibilityChartDescriptor` backed by `AXChartDescriptorRepresentable`. The Canvas is an explicit labeled image accessibility element and exposes the same live summary as its accessibility value. Both descriptor creation and update rebuild the chart title, summary, axes and series from the current visible-range display snapshot. The X axis names local/UTC time or elapsed time from the selected reference guide. The Y axis names the configured unit and formats values relative to the selected value-reference guide when one is active. Its coordinate range is the same computed range used by the renderer, including fixed limits, guides and forecast targets.

Only layout-visible streams become series. Lines and dots both off are described as “marks off” while their values remain available. Reconnect segments are separate series, so navigation does not imply a continuous line across a gap. A display query contributes at most 122 points per visible stream: 120 evenly spaced points plus the displayed minimum and maximum, deduplicated. The display query itself keeps first, last, minimum and maximum raw observations from each of 800 time buckets. The chart summary explains both reductions and calls out the latest visible raw observation from an exact query. When the renderer retains rows from its last completed query during refresh, accessibility presents those same visible rows and calls them displayed observations being updated. An exact historical query counts as ready even when its range excludes the stream's newest sample; the renderer's existing `currentDisplays` flag only controls the latest-point badge. A pending, failed or empty display query is described honestly. The summary also describes hidden stream count, guides, selection bounds and tracking mode, and visible forecast crossing estimates. Derived stream summaries identify the raw plot as distinct from the separate smoothed/rate estimates, and each derived trace reports its visible estimate count or loading/error state.

The transparent AppKit plot and ruler gesture overlays are hidden from the accessibility tree. Drag-only chart insertion targets are also hidden; the toolbar and stream-action menus provide their operations. The chart header's lines/dots buttons and image-only timeline controls have explicit labels. Chart actions offers Select Visible Time Range and Clear Selection. The plot navigation menu uses the app's native snapshot menu button for stable pan, zoom, frame and selection actions. The Session menu's Select Visible Time Range command has the ⌥⌘V shortcut and uses the existing focused-session and text-edit guard. Select Visible Time Range is disabled for a chart with no layout-visible streams, since an empty stream-ID set means all session streams in the existing selection model. Existing A/D pan, W/S zoom, F frame-selection and Escape clear-selection keys remain when SwiftUI has keyboard focus. Selection creation uses the existing session model and semantic undo path.

The opt-in, isolated acceptance fixture now seeds a second stream in its voltage chart. Its “Aux voltage” series begins with marks off, so native inspection can distinguish it from hiding the stream through Chart actions. The fixture still requires a new validated `/tmp/pipeplot-acceptance-*/acceptance.sqlite` path and uses a unique temporary socket. Ordinary launches receive no fixture data.

## Native acceptance and limits

The actual app was checked with a fresh isolated fixture database and temporary socket. The desktop accessibility tree initially exposed no plot element when only the chart descriptor modifier was attached. Adding an explicit Canvas accessibility element exposed the chart. Apple's Accessibility Inspector reached that intermediate chart as `AXUnknown`, labeled “Chart 1,” with no value; its advanced view did not show an `AXChartDescriptor` attribute. After adding the live summary as an accessibility value, the final build's desktop accessibility tree showed the voltage chart as a labeled image with two visible streams, latest displayed values of 11.5 mV and 6.89 mV at 16:41:29, the value guide, and the two-stage downsampling explanation. It did not stay in a “Loading” state. The decorative header image, transparent gesture overlays and drag-only drop targets did not appear as separate chart operations in that tree.

The native Plot navigation snapshot menu's Select visible time range action created a 29-second selection for both streams; the app's selection panel showed raw statistics. Panning earlier changed the visible range to 16:40:57–16:41:26 and the desktop accessibility-tree values to 11.1 mV and 6.47 mV without a permanent loading message. Hiding Aux voltage via the stream menu changed the chart summary to one visible and one hidden stream and removed Aux from its values. Restoring it returned both values, while the legend still identified Aux as “Marks off.” These checks exercised the actual app, menus and desktop accessibility tree, rather than only the descriptor helper.

The final image role, summary and current values were verified through the desktop accessibility-tree tool, not a final retarget in Apple's Accessibility Inspector; that retarget failed. Inspector had not exposed the structured chart attribute at the intermediate stage, so runtime export of `AXChartDescriptor` remains unverified. The helper tests establish descriptor construction and update only. Spoken VoiceOver/chart-audio behavior and a physical ⌥⌘V keypress were not verified. The focused command-routing test covers the shortcut action's session and text-edit guards, not native key dispatch. The Inspector connection was intermittently unavailable or the Mac locked during some attempts. Pointer behavior, window minimum-size layout, sleep/wake, notification delivery and the broader #14 native/lifecycle/resource acceptance were outside this pass.
