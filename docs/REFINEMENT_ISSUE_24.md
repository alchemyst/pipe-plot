# Swift refinement #24: ingestion boundary

`IngestionService` owns the socket server, protocol handler, connection registry, and guide-crossing detector. The server's `@Sendable` handler captures a worker and store, never the main-actor model. It performs handshake, registration, row persistence, acknowledgement, commands, and finalization on transport workers. A typed event mailbox makes one scheduled main-actor delivery for pending state; the model then refreshes snapshots, requests windows, ticks the first sample, and presents alerts. The mailbox's closure holds the model weakly.

## Synchronization and lifecycle

- `PipePlotStore`'s recursive lock guards all mutable metadata: sessions, attachments and owners, chart target and recency, undo/redo, continuation and epoch, counters, restore/termination state, persistence depth, committed rollback state, and the saved-open-session set. Its public `previouslyOpenSessionIDs` getter now takes that lock. Initialization finishes before publication. `SampleStore` independently locks its SQLite handle; store methods call it under the metadata lock. Direct public `samples` access remains an existing API, so callers must not infer that it updates store metadata.
- The registry lock serializes store registration with registry admission against session close/delete with connection detachment. A failed close leaves registered connections attached. An explicit later registration may reopen a closed session. Detached connections receive a best-effort `session_closed` error from workers; a separate 250 ms close deadline interrupts even a send stuck waiting for a socket write lock. Socket sends never run on the main actor or under the registry lock. Server stop closes active clients, waking handlers.
- Every registered handler finalizes in a deferred cleanup path for EOF, malformed input, send failure, and shutdown. Explicit finish and a terminating command finalize before their reply. The cleanup emits a lifecycle event even when a send fails, removes registry membership, clears crossing state, and closes the connection. Row acknowledgements still follow persistence.
- The mailbox coalesces session IDs and metadata, caps pending session IDs at 128, crossings at 128, and errors at 16, and schedules one main-actor drain per pending batch. Registration overflow reconciles all currently open, nondeleted sessions to preserve window requests; lifecycle overflow refreshes all snapshots. Crossing and error overflow report omitted counts explicitly, retaining the latest error. First-sample overflow refreshes all snapshots and advances the clock pulse once. Crossings retained within a batch remain FIFO.
