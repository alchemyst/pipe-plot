# Swift refinement #28: native session undo

`PipePlotStore` remains the sole semantic undo history. It keeps reversible domain records per session, retains the newest 200 actions, and rolls back failed persistence. `SessionUndoManager` gives each session one stable AppKit manager that reads the store's current action names and availability and forwards undo/redo to store replay through `PipePlotAppModel`. Undo registration is disabled in that manager, so AppKit does not build a second action stack. Failed edits, no-ops, and failed undo/redo therefore leave native availability in sync with the store. Edits made outside a focused view are visible immediately because the manager reads the store when queried.

`SessionWindowObserver` installs the manager through `NSWindowDelegate.windowWillReturnUndoManager(_:)`. This supplies the manager to SwiftUI's read-only `undoManager` environment value when the window asks after installation. The delegate proxy forwards other optional callbacks to the prior scene delegate and restores it when the observer detaches. Its `nonisolated(unsafe)` weak prior-delegate reference is assigned only at initialization; the nonisolated `NSObject` forwarding methods read it during AppKit's main-thread delegate callbacks. Hosted tests check forwarding and restoration.

Actual `WindowGroup` acceptance found a gap in that delegate route: SwiftUI had already cached a plain `NSUndoManager` for its `AppKitWindow` before the observer installed the delegate. LLDB inspection showed that the active window's delegate was the session proxy and the native `undo:` target was the window, but `window.undoManager` was still the plain cached manager. The default Edit menu therefore disabled Undo after a successful chart edit. `PipePlotCommands` now supplies a narrow Undo/Redo command group that resolves the session manager directly from the key window's delegate. While an editable field editor is active, it uses that editor's own undo manager. A per-session observable menu revision responds only to that window's key-focus and text-edit notifications; semantic snapshot changes already update `model.editRevision`. There is no second semantic stack or app-wide per-keystroke observer.

Core records for stream reassociation and forecast-target creation already group each compound edit into one semantic action; the bridge presents each as one named native action. Core action names now distinguish add/edit/delete guides, add/edit/delete time guides, and chart hide/restore.

The subsequent combined #33 plus native Undo repair gate passed 100 package tests (84 Core, 12 Transport, 4 CLI) and 69 hosted app tests, with two opt-in hosted skips. The combined strict build and format check also passed.

Hosted native tests exercise synthetic Cmd-Z and Shift-Cmd-Z key equivalents targeted at each of two `NSWindow` instances, menu enablement before and after undo/redo, an actual SwiftUI `TextField` receiving the session manager in its environment while its field editor keeps local undo, and an AppKit `NSTextField` field editor. They also cover edits made outside focus, failed edits and replay, no-ops, 200-action retention, independent session histories, close/reopen, Trash/restore, and single-step reassociation and forecast-target actions.

The hosted key-equivalent test targets the windows explicitly. It did not catch SwiftUI's cached manager; that regression was found by exercising the actual `WindowGroup` app with an isolated `/tmp` database. The new hosted test pre-reads the window manager before delegate installation and checks direct menu resolution. In the actual app, saving a chart Unit edit and hiding the inspector enabled semantic **Undo Axis Settings**; Undo changed the chart unit and Cmd-Shift-Z/Cmd-Z redid and reversed it. Reopening the inspector with no draft change left Save Unit disabled. Focusing its untouched text field disabled Undo/Redo, typing enabled local **Undo Typing**, and Undo restored the field text without changing the persisted chart; leaving the field restored semantic **Undo Axis Settings**. The menu focus checks used desktop interaction; the earlier semantic shortcut checks exercised Cmd-Z/Shift-Cmd-Z in that isolated app. Close/reopen coverage checks model and manager identity in the hosted process; a separate app relaunch was not exercised. Xcode also printed a CoreSimulator version notice and an App Intents metadata notice; neither failed the macOS test or build.
